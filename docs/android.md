# Android app

`apps/mobile/` holds an Android app, still in development. Each [release](https://github.com/bberka/TabLodge/releases/latest) attaches a signed APK (see [Install](install.md)), and pull requests that touch the app build a debug APK as a workflow artifact. It is a small link saver in the style of Raindrop:

- Bookmarks: browse columns (the first chip, **All**, lists every bookmark and is the one shown first; **Settings › Bookmarks › Show All in the bookmark list** hides it, as does **Hide All** in the menu you get by holding the chip (with Undo), and it is the same setting as in the extension; the three-dot menu is in the top bar), search (the round search button at the right edge, level with the floating tab bar (above a docked one), with the add button above it opens a search bar at the bottom of the screen, above the keyboard: a floating rounded bar with the floating tab bar, a banner across the screen with the docked one), add links (**Add several links** in the add drawer takes a list, one per line, and pasting several links into the link field switches to it), and tap one to open it. The add and Edit drawers have a **Notes** field; a bookmark's note shows under its address (one line in compact rows), and search finds it. Swipe a row right to delete it (with Undo) or left to edit it, or long press a row for its menu (Open, Open in…, Copy link, Edit, Move to column, Select, Share, Keep a copy, Delete). **Select** picks several, then open, export, move, or delete them together. Dragging three fingers down or up the list also selects: the rows between where the fingers landed and where they are now are picked, and the list scrolls near its edges. Selecting one row also offers Edit for its link, title, column, and note. **Open all** opens every link in a column. A column that Sources fills in the browser says which site it is saved from after its count in **Manage columns**; the phone does not save from sites itself.
- Share sheet: choose TabLodge from another app's share menu and a drawer slides up with the link and title filled in. When the share started the app, saving returns you to the app you came from by default; **Settings › Bookmarks › After sharing to TabLodge** can keep TabLodge open instead (**Close** by default, or **Stay in TabLodge**, synced with your other phones). Share an export file (JSON, CSV, HTML, Markdown, or a text list) from Files, a mail app, or Drive and the import preview opens, as with **Import from a file**; share a full backup (`.zip`, or a `.zip.enc` that asks for its password) and **Restore a backup** opens. The file is read once and its copy deleted. A file the app cannot read says so, and a photo or any other file is refused with a message: share the image's link instead. Text Chrome shares from a selection (it arrives in quotation marks) opens **Save quote**: the quote goes into the note of the page's bookmark (or of the page saved in a session, or a new bookmark in the last column you used) with a link that opens the page at the passage, the same note the extension's **Save quote** writes (rows show the link as **↗ Go to passage**; the edit drawer and exports keep the full address), and the snackbar offers Undo. A share that carries a link to the passage (`#:~:text=`) fills in the page from it. Chrome on Android 17 sent the text alone in testing, so the drawer says no page link came with it: paste the page's link, or type to search your bookmarks and pick one. When the share started the app and **After sharing to TabLodge** is **Close**, a short system message confirms the save instead, without Undo; with **Stay in TabLodge**, the in-app snackbar with Undo appears. Other shared words still open the save drawer, which has **Save as quote** for them, and **Save as a link instead** goes back. A note holds up to 10,000 characters; a quote that does not fit is refused with a message. TabLodge appears in the share menu for files of unknown type too, because Android sends a `.zip.enc` that way.
- Quick Settings tiles: pull down the notification shade, tap the pencil to edit the panel, and drag in **Save link** or **Search**. **Save link** opens the save drawer with the copied link filled in (an empty field when the clipboard holds no link), and **Search** opens the search on Bookmarks. On a locked phone the tile asks you to unlock first. Both open the regular library, never the private one, and work without a server. When a tile started the app, saving returns you to the app you came from, as with a share.
- Launcher shortcuts: hold the TabLodge icon for **Save link** and **Search**, the same two actions as the tiles.
- Bookmarks widget: add **Bookmarks** from the launcher's widget list and choose a column, or **All** for every column's links. It shows that column's links (up to 50, in your order) from the regular library, never the private one; tap a link to open it the way **Settings › Open links** says, the column name to open TabLodge on it, or the button beside it to choose another column. It is 2x2 at least and resizes up to 4x4, follows the light or dark theme, and shows a short message when the column is empty or gone or TabLodge has not saved anything yet. It reads a copy the app keeps up to date, also after a background sync, and never contacts the server.
- Saving the same link twice: a bookmark column or a session never takes a link it already holds, and the extension's **When a saved URL is saved again** setting, which syncs to the phone (the phone has no switch for it), decides the rest: **Reject duplicates** also skips a link saved in another column or session, **Allow duplicates** keeps another copy. A save that stores nothing says so and never reads as saved.
- Duplicates and details: the bookmarks **More actions** menu has **Remove duplicates**, which keeps the oldest copy of each saved address and can be undone. A session's **Edit details** (menu or swipe) changes its name and description, which show on its card and sync with the extension.
- List view: with many columns or folders, a row of chips is slow to swipe across. **Settings › Bookmarks › Show columns as** and **Settings › Sessions › Show folders as** each choose **Chips** (the default) or **List**, and the two screens are set separately. In **List**, the screen opens on one row per column or folder with its icon, name, and count, ending in **New column** or **New folder**. Tapping a row shows its contents under a bar with the name and a way back, and the Android back button does the same (the screen fades and the bar slides in, and Android's Remove animations turns that off); holding a row opens the chip menu below. A search looks through everything from either place, and a result that points at a column or folder opens it. Both settings sync between phones, not with the extension.
- Chip menus: holding a bookmark column chip selects it and opens the same menu as the three dots (Open all, Open all in…, Select, Put in order, Edit column, Move column earlier or later, Delete column, Remove duplicates, Manage columns); hold a session folder chip for Share (every chip has it, including All) and, for a folder you made, Edit folder (name, icon, color, and whether it colors the sessions moved into it) and Delete (its sessions move to Unfiled, with Undo). **New folder**, the last session chip, opens a sheet for a new folder's name, icon, color, and the color switch, with the same name rules as the extension: not empty, not "All sessions", not another folder's name (case ignored), at most 60 characters, and at most 200 folders. A name that is not allowed shows its reason under the field, and a library that is full says so as soon as the sheet opens. The rules live in `apps/extension/src/shared/session-folders.ts`, shared with the worker. Unfiled and Archived cannot be renamed or deleted, and the private library only opens and shares. TalkBack gets a More actions action on each chip.
- Import and export: **Settings › Import and export** has two buttons: **Import and export**, a menu of the actions below, and **Erase**. Import reads a file you pick or share to TabLodge, or links you paste, with the same reader as the extension: its own JSON, browser bookmark HTML, CSV, Markdown, link lists, and OneTab, Session Buddy, Tab Session Manager, Toby, Raindrop.io, Linkwarden, Karakeep, Omnivore, wallabag, Pinboard, and Mastodon bookmarks exports. A preview shows what it found and how many links are already saved or in the trash bin, which are skipped by default, and a file that holds both sessions and bookmarks asks which to import. **From another browser** explains the ways in (Android keeps each browser's data private, so no app can read another browser: Firefox's Share all tabs reaches TabLodge, other browsers share a page at a time, and bookmarks come in as an exported HTML file or through the extension). **Share and export** opens one sheet: pick sessions or bookmarks, then links, Markdown, a web page, JSON, CSV, or a bookmarks file, and **Share** hands it to Android's share sheet (a web page can also go to your server as a link, see Shared pages below); **Everything** saves a full backup ZIP in the extension's layout, with an optional password (a `.zip.enc` file, the same envelope the extension writes), which the extension restores. It covers the library on screen: in the private library it backs up the private library, and the file name says `private`. The phone has no snapshots, and its trash bin is not part of a backup, so those parts of the ZIP are empty, and the extension leaves its own snapshots and trash bin alone for such a file. **Restore a backup** reads a full backup ZIP you pick or share to TabLodge, from the phone or the extension (a password-protected one asks for its password first), cleans it the way the extension does, says how many items it had to leave out, and offers **Restore everything** (replaces the library on screen and brings back the phone's settings; it asks first, and keeps a copy of what it replaces so **Undo** in the message, or **Undo the last restore** in the same menu, which asks first, puts it back) or **Restore phone settings only** (only for a backup made on the phone; it asks first). A backup always replaces: the phone has no merge option. The extension's own settings that travel with the library keep their current values. **Statistics** lists how much is saved, and **Erase sessions**, **Erase bookmarks**, and **Erase everything** delete them after asking; settings are kept. Erase does not use the trash and leaves what is already in it. One session, a folder, a column, a single bookmark, or the selected bookmarks open the same sheet from their menus with **Share**; there is no separate Export.
- Trash (Android): what you delete on the phone (a session, a link taken out of a session, a bookmark, a bookmark column, a session folder, one at a time or several at once) is kept in a trash for the extension's **Trash retention** setting (7, 30 or 90 days; 30 until the library says otherwise; it syncs, and **Settings › Trash** changes it here too). **Settings › Trash** shows the count and opens the list, newest first, with **All**, **Sessions** and **Bookmarks** filters that show how many items each holds (Sessions covers sessions, saved links and folders; Bookmarks covers bookmarks and columns, as in the extension's trash bin). **Restore** puts an item back where it was: a session in its folder (at the top of it), a link at its old place in its session, a bookmark after the bookmark it followed (with a new id), a column with its bookmarks, a folder with the sessions that were in it. When the folder, column, or session is gone, the item goes to the first folder or column (or, for a link, into a new session of the same name) and a message says so. **Delete forever** removes one item and **Empty trash** all of them, after asking. Expired items are deleted when the app starts and when the trash is opened. The snackbar **Undo** still works as before. With a sync server connected, the trash syncs with the extension and other phones: what you delete anywhere can be restored on any device, and restoring or deleting it for good on one removes it from the others. Items the extension deleted restore here the same way (a link back into its session, a bookmark beside its neighbours, a column with its bookmarks). An item over about 200 KB, such as a session with hundreds of links, stays on the device that deleted it, and a server that predates the trash (its `/v1/status` lists no `trash` feature) leaves each device's trash local until it is updated. **Erase** does not put anything in the trash and leaves what is in it. The private library has a separate trash that only shows, in Settings, while the private library is open, syncs only with the private library, and is removed by **Delete from this phone**. The logic is tested in `apps/mobile/tests/mobile-trash.test.ts`.
- Sessions: saved sessions are listed by folder, as in the extension: **All** (without Archived), each folder with its count, and **Archived** last. Tap a tab to open it, or **Open all** for the whole session. Pull down on this list, or on Bookmarks, to sync now. The three-dot button in the top bar opens the menu of the folder on screen (Share, Edit folder, Delete folder), **Select sessions**, and **New folder**; it is hidden while the list view shows the list of folders. A phone browser cannot list its own tabs, so the app cannot capture them. Instead, share several links at once (in Chrome, select tabs in the tab switcher and choose Share tabs; in Firefox, Share all tabs) and a drawer asks whether to save them as bookmarks or into a session, where the first choice is a new session. Long press a session and choose **Select** to pick several; a bar at the bottom then opens, shares, moves, archives (or unarchives), or deletes them together, with Undo, and the header has Select all and Done.
- Open links: **Settings › Open links** picks where a link opens: the default browser (the default), an in-app tab that opens over TabLodge and returns to it when closed, or one of the browsers installed on the phone, listed with each app's own icon. **Private library links** takes its own choice, or follows the other one. Chrome ignores a request for a private tab from another app, so private links cannot be forced into incognito; point them at a private browser (Firefox Focus, DuckDuckGo, Brave) instead. If the chosen browser is gone, the default browser opens the link. Both choices stay on this phone. To open one link another way once, hold it and choose **Open in…**: the in-app tab, the default browser, or **Open with…**, Android's own chooser, which itself lists every installed browser and any app that takes the link, such as YouTube. **Open all in…** in a column's or a session's menu opens all its links the same way, and lists the browsers installed on the phone instead of the chooser, which picks an app for one link at a time. Neither changes the setting.
- Updates: **Settings › Check for updates**, at the bottom, asks GitHub for the latest release and compares it with the installed version. A newer release with an APK opens a dialog; **Download and install** saves `tablodge.apk` to the app's cache, showing the percentage downloaded on the button, and hands it to Android's installer, and Android asks once to allow installs from TabLodge. The answer is kept for an hour, so tapping again within the hour asks nothing; a failed check starts no wait. Only a tap sends a request. The logic is tested in `apps/mobile/tests/mobile-update-check.test.ts`.
- Open source licences: **Settings › About › Open source licences** lists every third party package in the app, with its version and licence: the npm packages in the JavaScript bundle and the Android libraries on the release classpath. Search by name or licence, and tap one for its full licence text. The list is made from each build, not by hand (see below). Code that React Native and Hermes link into their own libraries has no package of its own and comes under their entries. The extension ships the same kind of list as `THIRD_PARTY_NOTICES.txt`, linked from **Help › About and feedback**.
- Private library: a library of its own on the phone, edited like the regular one (bookmarks, columns, sessions, folders, import, export) and working without a server. **Settings › Private library** sets it up with a password, which the library always has (one from an earlier version without either asks for one before it opens); the glasses button (or Settings) opens it, and a lock beside it locks it at once. Saving a link or a shared list offers **Regular** or **Private** (a locked one asks for its password first). The data key is random and only a copy wrapped by the password is kept, in the same envelope the extension uses; the library itself is stored on the phone in the app's private storage, unsealed, so the password controls who can open it in the app and who can read it on the server. With a server connected it syncs with the private windows' library on that server, both ways, with every value sealed. When a server already holds a private library, setting up starts with its password, asked once: the phone takes that lock, the server's data comes in, and what is on the phone stays and merges. **Keep only on this phone instead** sets a password of its own and turns the private library's sync off, so it does not match the server until **Sync the private library** is turned on and the server's password is entered. **Lock now** forgets the key and keeps the data, **Erase private data** (also **Forgot it?** on the unlock drawer) removes it and asks for a new password (the server keeps its copy), and a password can be changed (it asks for the old one). A library from an earlier version that has no password does not sync until it gets one, so nothing leaves the phone unsealed; setting a password makes the phone send every record again, sealed. A password chosen on the phone never replaces the server's own: only joining the server's library, with its password, takes that lock. Nothing here needs a server: without one there are no spinners, banners, or prompts to connect, and the library syncs as soon as a server is connected, and stops when it is disconnected. **Lock automatically** (for a library with a password, on this phone only) is when the screen locks by default, or never, when you leave the app, or after 1, 5, 15, 30 or 60 minutes without a touch. The password cannot be recovered. It is one field with a normal keyboard, 4 to 128 characters of any kind, with a small note while a short or number-only one is typed; a 4-digit PIN from an earlier version keeps working. The button tells anyone holding the phone that a private library exists, so **Private library button** turns it off, on this phone only.
- Send to private storage: with a private library on the phone, holding a bookmark or a link in a session in the regular library offers **Send to private storage**, and the bar for selected bookmarks has **To private**. The link leaves the regular library without the trash, which syncs, and lands in the private library's **Sent from regular windows** column with its title, address, note, and tags, the same column the extension uses. A session left with no links goes too. The private library does not need to be open: the link waits in a list on the phone, outside the private library and as unsealed as the library itself, and moves in the next time the private library opens, once the snackbar's **Undo** is gone. Undo puts it back while it is still waiting. **Erase private data** drops the list; one that starts while a send is still being saved stops that send, and the link stays in the regular library. Sessions have no link selection on the phone, so a link in a session goes one at a time. The menu of a bookmark column and a session's menu also offer **Send to private storage** and send the whole column or session in one step with one **Undo**: a column keeps its name, color, icon, order, notes, and tags and joins a private column of the same name; a column a site's source column (`source-…`) saves into sends its bookmarks and stays, empty; a session keeps its name, link order, and saved date and arrives outside any folder. The extension does the same ([Private windows](private-windows.md#send-a-whole-column-or-session)).
- Starting over without the server's password: after **Erase private data**, a connected server that still holds a private library makes setup ask for its password first (when **Sync the private library** is on; with it off, setup asks for a new password for a phone-only library). If you no longer have it, choose **Keep only on this phone instead** and set a new password. The library then stays on the phone and does not sync. If the server cannot be reached while the drawer checks, it says so, offers **Try again**, and sets the library up on the phone only. To sync it later, turn on **Sync the private library** in **Settings** and enter the server's password, if it has one.
- Device names: with sync on, **Settings › Sync** has a Device name (a computer defaults to the browser and system, a phone to its make and model). New sessions and bookmarks record it. Session cards show where each was saved, and a bookmark's **Edit link** drawer says **Saved on** and the device; imported and older bookmarks have none. Each device has its own name, kept on that device; a rename does not change sessions already saved.
- Tags: each bookmark row shows its tags, the kind read from its address (movie, video, repo, read, and others) plus any you add. Long press a bookmark and choose **Edit** to add tags, or to remove the automatic one for that link; removing a tag offers Undo. **Filter by tag** in the three-dot menu lists every tag with its count and fills the search with `tag:`. Tags sync with the extension when the server has the `tags` feature.
- Page copies: long press a bookmark or a link in a session and choose **Keep a copy** to save the page's readable text on this phone, then **Open copy** to read it with the date it was kept and the original link, even after the page is gone. With a server connected the server fetches the page, so the site sees the server and not the phone; without one, or with a server too old for it, the phone fetches it. A page behind a sign-in cannot be copied. Copies stay on this phone and never sync. A copy goes to the trash with its link and is deleted when the trash is emptied; each holds up to 1 MB of text and the phone up to 25 MB, with a message when either is full. **Delete copy** in the reader removes the copy at once, with Undo in the message; the link stays saved. A backup includes them. The private library keeps no copies. The extension keeps copies of the open tab the same way.
- Saved images: a bookmark whose picture was kept with **Save image to** in the extension shows that picture's thumbnail in place of the site icon, once sync has brought it (the server needs the `thumbs` feature). Long press the bookmark and choose **Open image** to see the thumbnail larger, with its size, the date it was saved, and the name of the device that holds the full image. The phone keeps thumbnails only: it cannot save an image itself, and the full picture stays on the device that saved it. Deleting the image there deletes it on every device, with Undo. A backup from the phone carries the thumbnails.
- Preview when saving: the save drawer shows the page's icon and fills in an empty title, through your server when one is connected and straight from the site otherwise. **Preview links when saving** turns it off; it is on by default and syncs with your other phones.
- Site icons: with a server connected, icons load through it by default, so the server fetches them and sites never see the phone. **Settings › Bookmarks › Site icons** has a second choice, **Letter tiles only**, which asks nobody; it is the same setting as the extension's **Browser only** and follows your library to your browsers. A letter tile shows until an icon arrives or when a site has none. The extension's hover previews with images are not in the app. A server set up before icons and previews existed has no `preview` in its status; **Settings › Sync** then lists them among what waits for a server update (see [Self hosting](self-hosting.md#update)).
- Session actions: long press a session card, or use its **More** button, for Open all, Open all in…, Edit details (name, description, folder, and color), Add links (paste addresses into the session), Save links as bookmarks (into a column you choose or make), Share, Archive, and Delete (with Undo). Long press a link in a session for its menu: Open, Open in…, Copy link, Edit (its address, title, and notes), Add to bookmarks, Send to private storage (when the phone has a private library), and Delete (with Undo); holding a link never deletes it by itself. A link's notes, written in the extension or in that Edit drawer, show under its title in an open card (one line in compact cards); a changed title or note also changes every other saved copy of the same address, as in the extension, while a new address changes only that link. **Settings › Sessions** chooses what a tap does (show tabs or open all), what the main button at the foot of an open card does (Open all by default), and what a swipe right and left do; the default is Delete on the right and Archive on the left. A swipe on a session starts only on its header, so an open card's links keep their own swipes: **Swipe a link right** and **left** (Open, Edit, Add to bookmarks, Delete, or nothing; Delete on the right and Add to bookmarks on the left by default). An open card draws its first 100 links; a **Show more** button at its foot adds the next 100, so a session of thousands of links opens at once. The private library allows only opening and sharing.
- Settings sync: with sync on, your settings follow your other devices, including this app's own (tap and swipe actions, the main button on a session, compact sessions, the saved-on line, saving previews, and what happens after sharing). **Site icons** is the library's setting and syncs to browsers too. **Settings › Appearance** (including Message position, but not Glass effect) and background sync follow your other phones but never change a browser. Messages stay is the exception: it is the extension's setting too, so it syncs to browsers. The device name, where links open, and the private library's settings stay on each phone; [What stays on each device](PRIVACY.md#what-stays-on-each-device) lists them with the reasons. It is on by default and **Settings › Sync settings** turns settings sync off for one phone, the same switch the extension has. **Sync the private library**, next to it, turns off the private library's sync on one phone: it then stays on that phone and never reaches the server. The app's own settings travel in the library's `mobileApp` setting, which the extension keeps but does not use.
- Accent color (Android): **Settings › Appearance › Accent color**. The default is **TabLodge**, the app's purple, the same as the extension. **System color** is the phone's own Material You color (Android 12 and later, read once when the app starts; older phones and the iOS look keep TabLodge's own), and the palette and the palette swatch give a preset or any color. Colors are moved toward black or white until text in them is readable, and the choice syncs with the app's other look settings.
- Color picker (Android): the color drawers show the selected color's name, the preset swatches, and a palette swatch that opens hue and shade bars you drag (a screen reader steps them) and a hex field. A drag saves once, when the finger lifts.
- Session colors: a session can have a color, set in **Session details** in the extension (the same selector as column colors) and in **Edit details** in a session's menu on Android (long press the card, or the three-dot button in an expanded card). The color shows as a line on the top of the card in the extension and tints the card's tile on Android. It syncs with the session.
- Folder colors: a folder can have a color and a switch, **Update session colors to folder color when moved**, both set in **Edit folder** in the extension. The color tints the folder's icon in the folder selectors. With the switch on, a session moved into the folder (menu, drag, or **Session details**) takes the folder's color; a color chosen in the same **Session details** save wins, and sessions already in the folder keep theirs. The Android app keeps the color and the switch in sync, applies them when you move a session there, and sets them in **Edit folder** or **New folder**.
- Columns: every column selector shows the column's icon and color, and ends with **New column**, which asks for a name, an icon, and a color. The three-dot button in the top bar opens **Manage columns** (open, put in order, or change any column), **Edit column** (name, icon, color, and sites, or delete it, and its bookmarks move to another column or are deleted with it), **Put bookmarks in order**, and **Select bookmarks**. The icon button opens a drawer with a fuzzy search over the icon names and topics, the same as the extension's. The **Sites** section of a column's sheet lists the websites whose links go into that column when you save them: type a site such as `github.com` (which covers its subdomains) or `github.com/bberka` (only that path) and press **Add site**, or the close button on a site to remove it; the change is saved with **Save**. It shows an error under the field for something that is not a website, a site already listed, and a column that holds 50 sites, the extension's limit. The longest match wins, as in the extension. The color, icon, and sites sync with the extension, where a column's color is set in its Edit column dialog with the same selector as the accent color.
- Order: **Manage columns** moves a column up, down, to the top, or to the bottom, and **Put bookmarks in order** does the same for a bookmark inside its column. The order syncs with the extension. **Sort bookmarks**, in the three-dot menu and in **Settings › Bookmarks**, shows columns and All as Manual order, Newest first, Oldest first, Title A–Z, or Site A–Z. It is the extension's setting and syncs with it. Only a view: the stored order stays, and **Put bookmarks in order** appears only under Manual order.
- Excluded websites: **Settings › Excluded websites** lists the sites that are not saved from the phone, the same list as the extension's (it syncs both ways). An entry covers the site and its subdomains. A link to an excluded site is refused in the Save link drawer, and left out of a shared list.
- Settings search: the round search button in Settings opens a search box at the bottom of the screen that filters the cards and rows as you type. It matches a setting's name or its hint, so `swipe`, `tracking`, or `private` find what you mean. The header under the title then says how many settings it found (such as `3 results`), after typing pauses, and a screen reader announces the same count politely. **Restore default settings**, at the bottom, asks first and puts the app's settings back to their defaults; the library, server connection, phone name, and the extension's settings stay.
- Resetting a setting: holding a setting in Settings (or the **Reset to default** action TalkBack offers on it) opens a drawer whose button names the default it goes back to, such as **Reset to All tabs**, **Reset to On**, or **Reset to Off**. A setting that differs from its default carries a small accent dot after its name; at the default there is none. The dot is the only cue: the section's reset button, which appears only while the section has a changed setting, asks before it resets everything, and the app shows no one-time hint, since the dot appears exactly when a reset is useful.
- Messages: **Settings › Appearance › Message position** puts the snackbar with Undo at the top of the screen (the default) or above the tab bar, and **Messages stay** keeps it for a few seconds, twice as long, or until you tap it. Messages stay is the extension's setting of the same name and syncs with it; the position is this app's own and follows your other phones. Undo works for as long as its message is shown.
- Deleting: removing a session, a bookmark, a tab in a session, a session folder, or a column does not ask; a snackbar offers Undo. Sessions has the same add and search buttons as Bookmarks. Both lists show an **Up** button (**Scroll to top**) left of the add button once you have scrolled about a screen down, also while a search is open; it hides again near the top and scrolls back smoothly. The search bar of both screens understands the extension's search operators (`"exact phrase"`, `-word`, `site:`, `in:`, `kind:`, `col:`, `folder:`, `from:`, `after:`, `before:`), and its help button (**Search tips**) lists them in a drawer. Each screen's search looks only at that screen, and the line under the screen's title says how many results it found (`1 result`, `12 results`) once typing pauses; a screen reader announces it politely, without speaking on every key. When it finds nothing it adds **Nothing in Sessions matches. 3 results found elsewhere:** with results from the other places, ranked by the extension's search (Bookmarks lists sessions and the links saved in them; Sessions lists bookmarks, bookmark columns, and a fuzzy match on sessions and their links). Both also list the Settings sections that match, by name or by a setting they hold. With results of its own, a screen offers **Also search** under them instead. Asking for the other places says **3 more results found elsewhere:** above them. A link opens, a session or column opens its screen on it, and a Settings section opens Settings with its search showing that section. Dangerous actions in Settings, such as disconnecting or deleting the private library from the phone, still ask first.
- Resetting settings: holding a setting in Settings opens a drawer with **Reset to default** (TalkBack lists it as a custom action on the row), and a card's header shows a reset button (an icon, no text) only while something in that card differs from its default; it puts that card's settings back after asking, and the question reminds you that holding a setting resets just that one. **Restore default settings** resets everything; without sync that includes the settings shared with the extension, and with sync it asks whether to reset only this phone's settings or the shared ones too. The extension's Settings page matches: a changed setting has its own reset button, and a section header gets one that restores the whole section.
- Startup: **Settings › Startup › Open on** chooses the tab the app opens on: **Bookmarks** (the default, as before), **Sessions**, or **Last used**, which reopens the tab you left and, on Bookmarks, the column you had open. Shares, links, and the Quick Settings tiles still open where they always did. The choice syncs between phones, not with the extension, and the tab and column are remembered on this phone only.
- Behavior: **Settings › Bookmarks** chooses what a tap does (open or edit) and what a swipe right and left do (open, edit, move, delete, or nothing). **Settings › Links and titles** changes the extension settings that sync: clean titles, tracking parameters, and how addresses show. **Remove tracking parameters** is the extension's setting: it cleans a link when it is opened or copied, and a link is saved as it came, in both apps (the phone had its own clean-on-save switch before; it is gone). Choices such as swipe actions, how addresses show, session sorting, and whether columns and folders show as chips or a list are one line rows that open a drawer, and bookmark spacing and the session card options (compact cards, tab icons, saved on, expanded by default) are switches. **Settings › Sessions** also sets the **Session name** (the same styles and template as the extension; the name field on the save sheet is where it asks, and an empty field uses the style) and **Archive sessions not opened for**, which moves idle sessions into Archived when the app starts. Both are the extension's settings and sync. Settings that only make sense in a desktop browser are not shown, each with the reason in `apps/extension/src/shared/setting-scopes.ts`: new tab, side panel, context menus, windows, snapshots, and **Close tabs after saving** (the phone has no browser tabs), **Limit bookmarks shown at a time**, **Show at a time** (the phone shows one column at a time and scrolls it), and **Paste a link to add a bookmark** (the phone saves links from the share sheet and its Add button). The extension's Settings says so on each of them.
- Every setting in one line (each row shows the same line as its hint, and the search finds a row by its name or its hint): **Settings › Links and titles** has **Clean page titles** (drops counters such as (3) from titles), **Remove tracking parameters** (when opening or copying links, saved links stay as they are), **Shorten addresses** (hides `https://` and `www.`), **Mark links that are not secure** (an open lock beside `http://` links), and **Mark local links too** (addresses on this device or home network). **Settings › Bookmarks** has **Tap a bookmark** (open or edit), **Swipe a bookmark right** and **left**, **Under a bookmark title** (the full address, the site name, the address instead of the title, or nothing), **Compact bookmarks** (tighter rows), **Show All in the bookmark list**, **Site icons**, **Preview links when saving**, and **After sharing to TabLodge** (close to return or stay open). **Settings › Sessions** has **Sort sessions** (the extension's sort setting, so the last order picked in either place), **Show folders as**, the tap, main button, and swipe choices, **Compact session cards** (also hides the description, the tab icon strip, and the Saved on line), **Tab icons on session cards**, **Show where a session was saved**, and **Keep sessions expanded**. **Settings › Sync** has **Device name**, which the search finds as well.
- Shared pages: with a server connected, **Share and export** with **HTML page** chosen also offers **Get a link**, as a **Snapshot** (frozen copy) or a **Live link** (for a single column or session, updated automatically after edits sync), with an optional **password** on either. **Settings › Sync › Default shared link type** chooses whether **Get a link** starts as Snapshot or Live link and syncs with the extension. Right after sharing, the app copies the link and shows it with **Copy** and **Open**. A column's or session's **Share** lists the links made from it, and **Shared pages** in the Bookmarks and Sessions menus and in **Settings › Sync** lists every page with its kind (Snapshot or Live) and password status, each with Copy link, Open, and Delete, which asks first and makes the link stop working. The private library never uploads, and an older server explains which features need an update. See [Shared pages](self-hosting.md#shared-pages).
- Import from a link: **Import and export › Import from a link** reads a shared page's address into the import preview, with its columns or sessions as they were shared; password-protected pages ask for their password before reading. A shared page's **Add to TabLodge › Open in the TabLodge app** button opens the same preview through `tablodge://import?url=<page>`.
- Sync: it connects to your [sync server](self-hosting.md) with the same address and token as the extension, using the shared client in `apps/extension/src/shared/sync/`. While the app is in front, a live connection brings changes in within a second or two. When you leave the app, it first sends any change that is still waiting, then closes that connection and its timers, so it does not keep the radio or the battery busy. When you come back it reconnects and catches up. A change made with no connection is kept and goes out by itself once the server is reachable again. With the app closed, **Settings › Sync › Sync in the background** (on by default) lets Android run one sync about every 15 minutes, or later when it saves battery by batching apps or the phone is idle. It waits for a network, opens no live connection, and redraws the Bookmarks widget when something changed. Turn it off and changes from other devices show up when you open the app. The private library never syncs in the background: it catches up when you open it. **Settings › Sync** shows the server's version and lists what does not work until the server is updated, such as bookmark notes staying on the phone, with a link to the update steps. When the server and the app speak different versions of sync, sync stops and says which one to update; the library on the phone stays as it is. While either problem lasts, a banner at the top of Bookmarks and Sessions says so, with **Open Settings**. Stopped sync stays there until the server or the app is updated. A server that lacks features can be dismissed with **Dismiss**, and the banner returns when the server reports another version or lacks a different set of features. The dismissal stays on the phone.
- App icon: on Android 13 or newer, turn on themed icons in the launcher (on Pixel: **Wallpaper & style › Icons**) and TabLodge's icon is tinted in the wallpaper's colors, light or dark with the system theme. Otherwise it keeps the purple mark on a pale lavender background, in every launcher shape. Android gives an app one launcher icon, so it cannot swap to a different one when the phone goes dark; the splash screen does follow the system theme, with a brighter mark on the dark background. The images come from `pnpm run mobile:icons`, so there is no second copy of the mark to edit.
- Look: **Settings › Appearance** chooses a **Theme** (the phone's own, light, or dark), the **Accent color**, a **Style** that is Automatic by default (the Material look on Android, the iOS look on an iPhone) or set to the Android or iOS look, and turns the floating tab bar on or off, which is on by default. **Floating bar size** is full width, small while scrolling, or always small; the bar leaves room on its right for the round search button. **Tab names** (for either bar) shows the name under every tab (the default), under the open tab only, or nowhere; a small bar never has room for names. The docked tab bar is the same in both looks: a tall bar with a pill behind the selected icon. It has a **Search** button at its right end, on the screens that have search; the floating bar keeps its own round search button beside it. While a search is open the floating bar steps aside. The search bar keeps the same size whether or not its input has focus, and the Back gesture hides the keyboard first and then closes the search. Everything in **Appearance** follows your other phones but never changes a browser, which keeps its own theme. **Glass effect** is the exception: it stays on this phone, since the frost depends on its graphics. With the iOS look, the floating tab bar, the round search and add buttons, and the floating search bar are drawn as frosted glass: a blur of the content scrolling behind them under a translucent tint, with a thin bright rim and a soft highlight along the top edge. It approximates iOS 26's Liquid Glass and cannot bend the light behind it as the real material does. The blur needs Android 12 or later; older phones get the same tint without it. **Glass effect**, shown only with the iOS look and on by default, turns it off for solid surfaces, which scroll more smoothly on a slow phone. The Material look and the docked bar are not glass.

- Not planned on purpose: the app keeps session management simple, because it is a standalone app and not an extension, and sessions are hard to manage on a small screen. It will not get splitting a session into two or merging sessions ([#210](https://github.com/bberka/TabLodge/issues/210), [#209](https://github.com/bberka/TabLodge/issues/209)); use the extension for those, and the changes sync back. It also does not enforce the library's size limits or clean records the way the extension does when it loads them ([#217](https://github.com/bberka/TabLodge/issues/217)); the extension trims and repairs them on the desktop.

[ADR 3](adr/0003-mobile-app-framework.md) explains the framework choice, [ADR 4](adr/0004-android-quick-settings-tiles.md) the Quick Settings tiles, and [ADR 6](adr/0006-android-bookmarks-widget.md) the Bookmarks widget. The app is not published and is not part of the extension build.

To run it you need JDK 17 or newer and the Android SDK (`ANDROID_HOME` set). `pnpm run mobile:android` builds a development build and installs it on a connected device or emulator, and `pnpm run mobile:start` serves the JavaScript to it. `pnpm run mobile:apk` builds a standalone APK of the current checkout (JavaScript bundled in, arm64 only) at `apps/mobile/dist/tablodge-local.apk` for trying on a phone, and `--install` installs it on the connected device. It is signed with a local debug key, so it cannot update the released app: uninstall that first, which removes its local data. `pnpm run mobile:doctor` checks the Expo setup, and `pnpm run mobile:export` bundles the JavaScript without a device. `pnpm run mobile:licences` writes the Open source licences list to `apps/mobile/src/about/licences.generated.json`, which git ignores: it bundles the app once with source maps to see which npm packages Metro includes and, when `android/` exists, asks Gradle for the release runtime classpath (`--native` makes `android/` required). A package without a licence id or licence text stops it, so a build cannot ship one the list leaves out. `mobile:export`, `mobile:android`, and `mobile:apk` run it first, and `mobile:start` writes an empty list when none exists. The extension build uses the same code (`scripts/third-party-notices.ts`) for its `THIRD_PARTY_NOTICES.txt`. In a development build, the app starts with the same sample sessions and bookmarks as `dev:chrome --seed-data` (the fixture in `apps/extension/src/shared/dev-fixture.ts`), once, when its library is empty and no server is connected. Set `EXPO_PUBLIC_SEED_DATA=0` to start empty instead. **Settings › Development** can load the samples again or clear the library. Sample data never reaches a server: those buttons are off while a server is connected, and connecting removes the samples first. Release builds do not contain the sample data. The sharing logic is tested in `apps/mobile/tests/mobile-library.test.ts` and `apps/mobile/tests/mobile-sync.test.ts`, and the search over the other places in `apps/mobile/tests/mobile-search-elsewhere.test.ts`.
